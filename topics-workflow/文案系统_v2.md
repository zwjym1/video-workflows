# 秘书丞 · 文案系统 v2

版本：v2.0 · 2026-10-20（Asia/Shanghai）  
适用：竖屏科技科普口播 + 标题封面  
前置：**必须已有** `field_douyin.md`（见《选题采集系统_v2》）  
配对：`口播_自检清单.md`

---

## 黑白结论（先看这 6 条）

1. **无实地包 → 不得定稿口播 / 不得开渲。**
2. **禁止万能口播壳**：`看见没 → 点名 → 因为 → 带走 → 搜xxx`。每条先定「这条的声音」，再写逐句。
3. 结构只认：**现象 → 因为什么 → 一句钉死**；**0–3s 奇观**；**一句一字幕**。
4. 大博主不是套模板：何同学偏故事、不白吃偏类比、差评君偏吐槽、毕导偏框架——**参考开头拆解，禁止套他们的壳当我们的壳**。
5. 先标题封面，再口播（影视飓风逻辑）；标题必须能埋实地包里的搜索词。
6. 日更两更质量不够就空槽；口播听着像「同一人念提纲」= 文案失败，整段重写。

## 一、谁写、何时写

| 步骤 | 谁 | 输入 | 输出 |
|---|---|---|---|
| 实地包 | 通政使 | 看片 | `field_douyin.md` |
| 定声音 + 写口播 | **秘书丞** | 实地包 + 事实表主论断 | `script.md` |
| 排期提醒 | 允知 | 槽位状态 | 不写口播、不定语气 |
| 过目 | 用户 | script / 预览 | GO 才配音 |

秘书丞拿到包之前：最多列「钩子假设」，**不定稿 8 句口播**。

## 二、口播写作流程（强制顺序）

```
① 读实地包（开头原文 / 评论高频 / 相关搜索）
    ↓
② 定「这条的声音」一句话（人设语气 · 本条唯一）
    ↓
③ 拆 1–2 条对标开头（学结构：第几秒出奇观、第几秒钉死；不抄金句）
    ↓
④ 写 0–3s 画面钩子（先画面后台词）
    ↓
⑤ 按 现象→因为什么→一句钉死 写逐句（一句一字幕）
    ↓
⑥ 标题 3 候选 + 封面一句（埋搜索词）
    ↓
⑦ 自检表全过 → 交用户过目 → 才配音
```

**禁止**：事实表填完直接套固定短句模板出稿。

## 三、先定「这条的声音」

每条选题在 `script.md` 文首必须有一块：

```markdown
## 本条声音
- 一句话：________（例：冷静拆穿误会 / 科技馆讲解员带一点兴奋 / 吐槽完立刻给原理）
- 对标参考（只学结构）：________（从名单选 1 个主参考）
- 本条禁止的语气：________（例：禁止资讯播报腔、禁止「带走：」口号）
- 来自实地的理由：评论在问「___」；爆款开头是「___」型 → 所以我们选这种声音
```

### 对标名单（只学开头结构，不套句式）

| 参考 | 常用来学什么 |
|---|---|
| 何同学 | 故事感、物件开场 |
| 不白吃 | 类比一口说清 |
| 青禾记 | 生活场景进原理 |
| 孙怀庆博士 / 李论科学 | 严谨但仍口语 |
| 漫士沉思录 | 思辨钩子 |
| Ele实验室 / 浙大猫学长 | 实验/演示画面锚 |
| 毕导 | 框架清晰但不念提纲 |
| 差评君 | 吐槽切入，马上给干货 |
| 影视飓风 | 标题封面先行、前 2s 留存 |

同周两条选题**不要**共用同一个声音标签。

## 四、结构与时长

### 硬结构
| 段 | 作用 | 要求 |
|---|---|---|
| 0–3s | 现象 / 奇观 | 肉眼停得住；禁止「今天讲三步」「大家好」 |
| 中段 | 因为什么 | 1–2 句机制；中段必须有**视觉锚**（实拍/3D/录屏），禁纯讲 |
| 收束 | 一句钉死 | 可搜、可复述；不是「关注我」「带走：」口号壳 |
| 可选尾 | 搜索词落点 | 自然埋词，禁止生硬「搜 xxx」当第八句固定位 |

### 时长目标
- 竖屏主形态：**30–45s**（快评可 ≤35s）
- 均播预期至少过 **12s**（广交会级 7s = 结构失败）
- 一句优先 **≤14 字**（难句可两行，仍算一句一字幕）

### 字幕
- 一句一条、整句替换
- 白字黑边，下 1/3
- 每屏最多 2 个色高亮
- 数字/型号与画面锚同帧

## 五、禁止清单（文案红线）

### 万能壳（出现即重写）
- `看见没？` 开场（除非画面本身迫使这句，且本条声音就是街头拦人款——默认禁用）
- `点名产品/事件 → 因为 → 带走：→ 搜 xxx` 五段金壳
- `一看 / 二算 / 三打` 及任何步骤编号开场
- `今天给大家讲三个…`
- 每条都用「带走：」当倒数第二句

### 内容禁止
- 无事实表对应的数字、时间、「谁说了」
- 「对标 Sora / 全部都是假的」等绝对化或未核表述
- 教程长步骤、展会导览腔
- 组件、定位、地缘立场
- 一句多字幕、PPT 念稿

### 流程禁止
- 无实地包定稿
- 先写完全稿再补「声音」标签糊弄
- 抄爆款口播原文当自己的（学结构可以，原句不行）

## 六、好句 / 坏句对照

> 坏句多来自本账号曾用模板；好句示范「先声音、后结构」，可改写不可当新壳。

| 场景 | 坏（模板腔） | 好（有声音） | 为什么 |
|---|---|---|---|
| 开场 | 看见没？这动画不是剪的。 | （画面已经在疯）它不是视频。——是网页自己在跑。 | 坏句每条都能套；好句贴画面机制 |
| 开场 | 今天讲摩托为什么能水上漂。 | （实拍冲水面）它没漂。 | 坏句无奇观；好句 0s 反常识 |
| 因为 | 因为它写代码——不是一帧帧画画。 | 模型吐出的是 HTML。浏览器一开，自己动。 | 坏句抽象「写代码」；好句可看见 |
| 钉死 | 带走：不是画视频，是写能动的网页。 | 记住这句：能动的网页，不是生成的视频。 | 删「带走：」口号壳 |
| 搜索 | 搜 DeepSeek 动画。 | （片尾小字/口播自然）DeepSeek 动画——搜得到同一波演示。 | 坏句生硬 CTA；好句可删可留 |
| 中段 | 第一看结构，第二算力，第三落地。 | 中段直接切受力箭头 / 录屏两刀证明 | 步骤编号=已判死刑结构 |
| 资讯 | XX 更新了，我们来看看。 | 评论都在问「能不能商用」——先看官方演示卡在哪。 | 用评论高频定切口 |

**自测**：把本条 8 句里的专有名词抠掉，若还能原样贴到另一选题上 → 整段重写。

## 七、与实地包如何对接

打开 `field_douyin.md` 后，秘书丞必须填进 script 的对照表：

| 实地字段 | 文案动作 |
|---|---|
| 爆款 0–5s 画面 | 决定我们 0–3s 拍什么 / 录什么（可差异化，勿同构图抄） |
| 爆款口播原文 | 只拆「第几秒出判断句」；**禁止整句复用** |
| 评论高频 Top | ≥1 句口播或字幕直接回答最高频问题 |
| 相关搜索词 | 标题必含 1 个；口播可自然出现 1 次；简介再堆长尾 |
| 撞车判断 | 同切口已满 → 换钉死点或空槽，不硬写 |

无上表 → 视为未对接实地，过目一律打回。

## 八、标题与封面规则

### 标题
- 先写 **3 个候选**，选 1 个定稿
- 必须含：可搜词（来自相关搜索）+ 好奇心（为什么/真假/不是…是…）
- 标题的问题，片子里必须给答案
- 不夸大、不碰红线词

### 封面
- 一句大字（≤12 字优先）能**直接证明**标题
- 画面主体与标题同指一事；IP 若出镜须和主体有互动
- 禁止纯文字海报、禁止「震惊」空洞词

### 输出块（script 必备）
```markdown
## 标题 3 候选
1. ★ …
2. …
3. …
封面一句：…
搜索词（来自实地）：…
```

## 十、写稿后 → 渲染前

1. 逐句对事实表：无对应就删或补来源
2. 抠专有名词自测（见第六节）
3. 突发题渲染前再搜反转
4. 简介：来源列表 + AI 声明 + 搜索词
5. 用户 GO 后才配音 / 开渲
