## 3. BGM 使用规范

### 3.1 分段打法（科技解说，口播为主）

先给硬数字，都是我在这条片子上用 ffmpeg 实测的，不是拍的：

- 口播干声：**-19.4 LUFS**（整合），真峰 -1.3 dBFS，语速 7.44 字/秒。
- 成片（v1）：**-14.2 LUFS**，真峰 -1.1 dBTP。抖音/B 站都在这个区间，别动。
- 对标片（小白debug 两条）：-13.8 和 -14.0 LUFS，真峰 -0.1 / -0.5。**他的峰顶得比我们高 1dB**，说明他在最后一级压得更狠，响度上我们还差半个身位。

| 段落 | 时长 | 音乐类型 | 音量（相对口播） | 处理 |
|---|---|---|---|---|
| **开场钩子** 0–3s | 3s 内必须出声 | 单音色 hook / 一个和弦砸下来，或直接进鼓 | 先给 -22 LUFS，第 1 句口播进来时立刻压到 -30 | 前 3 帧淡入（0.1s），不要从 0 音量慢慢爬 |
| 钩子铺底 3–40s | ~42s | 有鼓但稀疏，BPM 90–130 | **-30 ~ -28 LUFS**（比人声低 9~11 dB） | 高通 45Hz、2.3kHz 挖 -4dB |
| **讲解主体** | 主体 | 循环稳、无人声、旋律重复度高 | **-32 LUFS**（比人声低 12~13 dB） | 高通 45Hz + 2.3kHz 挖 -4dB + 150Hz 挖 -3dB；**不要整条低通**；最多在 16kHz 以上做一个很缓的高切，把刺耳的镲片削掉 |
| **重点强调** | 5–15s / 次 | 音乐**停**，只留口播 + 一个音效 | 音乐 -60 以下或直接静音 | 留白 **0.8–1.2s**（够说完一个短句，不够让人走神）。参考：我们渲染器在两句口播之间插 8 帧 = **0.267s**，留白必须明显长于它才听得出来 |
| **章节卡** | 2.9–4.7s | 音乐回到主题动机（drop / 主 riff 第一句） | -26 LUFS（比分段主体 +4~6 dB） | 这一下必须是**重拍**，卡片才有「砸下来」的感觉。长度取到「正好补齐下一小节线」，不要固定值 |
| **结尾** | 10–25s | 上扬然后**收**，不要渐弱到没 | 从 -30 抬到 -26，最后 1.5s 淡出 | 收尾用「最后一小节完整放完再淡出」，不要半句切掉 |

三条容易踩的：

1. **别整条都低通**。低通滤波（lowpass）听着「不抢人声」，实际是把高频瞬态全削了，鼓点变闷，卡点就废了。正确做法是**只在 2–3kHz 挖一个宽 Q 的坑**（人声齿音和清晰度都在这），其余频段留着。
2. **静音留白要真静音**。我们在 ③访存瓶颈和 ⑥重算各留了一次白，效果比堆音效好。但留白前后要有 0.15s 的淡出/淡入，否则会有咔哒声。
3. **章节卡之间不要每章都换曲**。换曲=换调性=耳朵要重新适应，一章一换会累。**一条片子最多 2–3 个音乐主题**，靠「同一首曲子的不同段落」来做变化（前奏 / 主段 / 爆发段）。

### 3.2 口播时的 BGM 音量

用相对值，不用绝对值，因为你的口播电平每次都会变：

- **稳态铺底：比人声低 12–13 LU**（人声 -19.4 → 铺底 **-32 LUFS**）。这是「听得见但不干扰」的甜点。
- **可接受区间：-10 ~ -14 LU**。低于 -14 就是「听不见，白买了」；高于 -10 开始跟人声抢中频。
- **想要音乐更有存在感**（比如总装揭晓），可以抬到 **-8 LU**，但那段必须**没有口播**，或者口播密度很低。
- **不要用 dBFS 峰值去判断**，一定要用 LUFS / 短时 LUFS。同一段音乐峰值 -6dBFS 可能比另一段 -3dBFS 听起来更响，因为前者是持续能量、后者是一个尖峰。

实测换算：We Never Remix 在 **-17.5 dB 增益下是 -32.0 LUFS**，正好比口播（-19.4）低 **12.6 LU**。换成 -19 dB 增益会掉到 -33.5，比口播低 14.1 LU，偏轻。所以「减 19 dB」≠「-19 LUFS」——**每次换曲都要重新量，别套公式**。

**Ducking（侧链压缩）实测参数**（ffmpeg `sidechaincompress`，我在这条片子上跑通了）：

```
[bg][vo]sidechaincompress=threshold=0.05:ratio=5:attack=18:release=400:makeup=1
```

实测效果（全片 370.5s）：铺底静止在 **-32.0 LUFS**，挂上侧链后变成 **-37.7 LUFS**，即**压下 5.7 dB**。这个深度刚好——再多（>10dB）会听见音乐「呼吸」，再少（<4dB）盖不住。

（这是全片平均值，含口播停顿处音乐回来的部分；单看「正在说话」的 40 秒窗口，压低会到 8–12dB。）

- threshold **0.05**（约 -26dBFS）→ 口播一起来就触发
- ratio **5:1** → 够硬但不至于抽气
- attack **18ms** → 快于一个音节，慢于爆音
- release **400ms** → 句间停顿不会把音乐弹回来（弹回来会「抽气」）

**如果你不想上侧链**，就用固定 -32 LUFS 的铺底 + 章节卡处手动抬 6dB。省事，效果差 20%。

### 3.3 母带

两遍 loudnorm（一遍测量、一遍套参数），别用一遍，一遍是动态压缩会压掉起伏：

```
# 第一遍：只测量
ffmpeg -i pre.wav -af loudnorm=I=-14:TP=-1.5:LRA=9:print_format=json -f null -
# 第二遍：把测出来的 5 个数字填进去，开 linear
ffmpeg -i pre.wav -af "loudnorm=I=-14:TP=-1.5:LRA=9:measured_I=-19.49:measured_TP=-4.29:\
measured_LRA=4.70:measured_thresh=-29.90:offset=0.50:linear=true,\
alimiter=limit=0.891:attack=3:release=60:level=disabled" out.wav
```

我实测这条链路（全片 370.5s 的完整混音）跑出来 **-14.1 LUFS / 真峰 -1.5 dBTP / LRA 4.2**。目标是 -14 / -1.0，峰差 0.5dB。想再顶一点就把 `limit` 从 0.891 提到 0.912（=-0.8dBFS），但**别超过 -1.0**，抖音转码会再压一层。

## 4. 怎么在剪辑里做「卡点」

### 4.1 先认清一件事：我们现在**卡不上**

我把成片场景检测跑了一遍（`ffmpeg select='gt(scene,0.2)'`），原始命中 28 个，把 1.3 秒内连续的转场合并后得到 **22 个硬切事件**（平均 16.8 秒一次），拿去对网格：

| BPM | 章节卡离最近**小节线**（平均 / 最差） | 切点离最近**拍**（平均） | 落在 ±80ms 内的切点 |
|---|---|---|---|
| 117.45（We Never Remix） | 339ms / 831ms | 141ms | 8 / 22 |
| 120 | **551ms / 970ms** | 123ms | 6 / 22 |
| 128 | 478ms / 925ms | 102ms | 9 / 22 |
| 150 | 405ms / 700ms | 105ms | 6 / 22 |

**没有一个 BPM 能让现有时间轴卡上。** 原因是章节卡的时长是按「字幕念完」算的（84 帧起步），跟音乐毫无关系。所以「卡点」不是选歌的问题，是**时间轴要先量化**。

人耳对「音画不同步」的容差：鼓点类约 **±30ms** 才叫「卡上」，±50ms 是「差一点」，**超过 ±80ms 就是明显没对上**。章节卡那栏是**半秒级**偏差，观众听到的就是「音乐跟画面毫无关系」——不是没卡上，是根本没往这上面做。

### 4.2 强拍对什么、弱拍对什么

| 音乐位置 | 周期（120BPM） | 对哪些画面事件 |
|---|---|---|
| **强拍 / 小节第 1 拍（downbeat）** | 2.00s | 章节卡砸下、镜头硬切、标题牌弹入、「所谓 XX」的定义句落地 |
| **第 3 拍（backbeat 后半）** | 2.00s | 大块元素换位、图表换页、代码行整段替换 |
| **弱拍 / 8 分音符** | 0.25s | 图标飞入、文字逐字弹出、数字滚动的**起点**、连线生长 |
| **16 分音符** | 0.125s | 只给「密集小动作」：进度条推进、光标闪烁、粒子。**别把语义事件放在这层**，太快了观众反应不过来 |
| **每 4 拍 = 1 小节** | 2.00s | 一个完整的「信息单元」：一句话 + 它对应的画面动作 |
| **每 16 拍 = 4 小节 = 1 大句** | 8.00s | 一个论证回合：提出问题 → 给类比 → 给数字 → 落地术语。**章节切换按这个大句走，不按小节走** |

一句话口诀：**小节线管「换」，8 分管「动」，16 分管「闪」；4 小节管「讲完一件事」。**

### 4.3 实操顺序（这个顺序不能反）

1. **先定 BPM，再写分镜**。不是先写分镜再找歌。定 120 是因为 @30fps 下 1 拍正好 15 帧、1 小节 60 帧、4 小节 240 帧，**全是整数帧**，不会因为取整产生累积漂移。150 BPM 也干净（12 / 48 / 192 帧）。
2. **把章节边界对齐到小节线**。我们这条片子的做法：正文不动，**把章节卡的长度改成「补到下一小节线」**，卡片从 2.80s 变成 2.89–4.66s，观众基本无感，但从此每章开头都踩在重拍上。全片 370.5s → 380.0s，多 9.8 秒。
3. **字幕时间轴不要跟着动**。字幕是跟着口播走的，口播不动，字幕就不能动。动的是**卡片和空白**。
4. **最后才铺音乐**。音乐服从画面，不是画面服从音乐。

### 4.4 如果不想改时间轴：切片重排

我写了个工具 `tools/bgm_slice.py`，逻辑是反过来——让音乐服从画面：

- 每一章单独从原曲里取一段，**素材起点强制选在小节线上**
- 长度裁到正好等于这一章
- 接缝加 0.12s（≈4 帧）交叉淡化，落在章节卡的重音上

我用 We Never Remix 对实测的 11 段章节边界实跑了一遍，输出 370.500s 与计划完全一致。听感上因为是「同一首曲子的不同小节」在拼，调性和配器都没变，只有过渡处的鼓会有一点点断——**但那一断正好发生在章节卡上，被卡片音效盖住**。

代价：这条轨只能配这一版片子。改一个镜头就得重跑。

## 5. 卡点事件映射表

先交代方法：**我没有拿代码里的时间轴去推**。我把成片音轨解码成 8kHz 单声道，然后把 86 条配音逐条和它做互相关，**实测出每一句在成片里的真实起点**（这个值和渲染器里的模型算出来的差了 17 秒，说明模型不可信，只有实测算数）。下面的 v1 时间全部是实测值。

### 5.1 事件 → 节拍位置（规范）

| 画面事件 | 音乐位置 | 为什么是这层 | 提前量 | 密度上限 |
|---|---|---|---|---|
| **镜头硬切** | 小节第 1 拍（强拍） | 硬切是最大的视觉断裂，必须踩最重的点 | 0 帧（同帧） | 每小节 ≤1 次 |
| **章节卡 STAGE N 砸下** | 小节第 1 拍（强拍） | 章节卡是天然的段落重音，也是音乐的 drop 点 | 0 帧 | 每章 1 次 |
| **标题牌 / 术语标签弹出** | 小节第 1 拍，或第 3 拍 | 一个完整语义单元的开始 | **抢 2–3 帧**（67–100ms） | 每小节 ≤2 次 |
| **数字滚动 · 起始** | 8 分音符 | 滚动是持续动作，起点对齐就够 | 抢 1–2 帧 | 每小节 ≤1 组 |
| **数字滚动 · 定格** | 下一个强拍 | 定格的「咔」才是听觉锚点，比起点重要 | 0 帧 | 同上 |
| **图标 / 方块飞入** | 8 分音符（弱拍） | 元素轻，落弱拍更自然 | 抢 2 帧 | 每小节 ≤2 个 |
| **文字逐字弹出（打字机）** | 16 分音符起，**末字落 8 分音符** | 逐字是过程，末字才是信息 | 0 帧 | 每句 1 次 |
| **转场闪白** | 只放在 4 小节大句的接缝，第 1 拍 | 闪白是最强刺激，用多了会疲劳 | 0 帧 | **全片 ≤4 次** |
| **章节卡（大结构）** | 4 小节线的第 1 拍 | 16 拍 = 一个完整论证回合 | 0 帧 | 每章 1 次 |
| **「所谓 XX」定义句落地** | 小节第 1 拍 | 每章的结论，观众的记忆点 | 抢 1 帧 | 每章 1 次 |
| **静音留白 · 开始** | 强拍（在小节线上切） | 在小节线切听着是「设计」，在半拍切听着是「坏了」 | 0 帧 | 每片 2–3 次 |
| **静音留白 · 结束** | 下一个强拍 | 回来必须是完整 downbeat，不要渐入 | 0 帧 | 同上，留白 0.8–1.2s |
| **BGM 换段 / 加层** | 4 小节线 | 加鼓、加弦乐这种「升级」动作 | 0 帧 | **每片 ≤3 次** |

口诀：**小节线管「换」，8 分管「动」，16 分管「闪」；4 小节管「讲完一件事」。**

「抢帧」是行话：画面比声音**早** 2–3 帧（67–100ms）出现，主观上才觉得「同时」。严格同帧反而显得画面慢半拍。

### 5.4 为什么 120 BPM

拍 = 1800 ÷ BPM 帧；小节 = 4 拍；大句（16 拍）= 4 小节。

| BPM | 1 拍 | 1 小节 | 16 拍大句 | 全整数帧？ |
|---|---|---|---|---|
| 100 | 18.0f | 72.0f | 288f | ✅ |
| 112.5 | 16.0f | 64.0f | 256f | ✅ |
| **120** | **15.0f** | **60.0f** | **240f** | ✅ |
| 126（We Never 原曲） | 14.29f | 57.14f | 228.6f | ❌ 每拍 .29 帧 |
| 128（Sky High / Hope） | 14.06f | 56.25f | 225.0f | ❌ 每拍 .06 帧 |
| 150 | 12.0f | 48.0f | 192f | ✅ |
| 175（METAMORPHOSIS） | 10.29f | 41.14f | 164.6f | ❌ 每拍 .29 帧 |

只有 **100 / 112.5 / 120 / 150** 能让拍、小节、大句全落在整数帧上。

**120 最优**：We Never Remix 117.45 → 120 只要 **+2.2%**；Sky High / Hope 128 → 120 要 **−6.25%**，都在 atempo 听不出音染的 8% 以内。150 太急，讲原理的段落会显得赶；100 / 112.5 太慢，撑不起钩子的信息密度。

**128 要避开，但原因不是「漂移」**——128 的 16 拍大句正好 225.0 帧，是整的，不会累积漂。问题是**拍点落不到帧上**：每拍 14.06 帧，四舍五入到 14，25 拍之后音乐和画面差整整一拍。所以 128 只能靠「每个事件单独吸附」救，不能靠时间轴整体量化。

## 6. 三条落地路径

**路径 A · 切片重排**（0 改代码，今天就能出）
`tools/bgm_slice.py` 按章节边界把一条曲子切成 11 段重拼：起点强制落小节线，长度裁到正好等于该章，接缝 0.12s 交叉淡化。我拿 We Never Remix 对实测的章节边界（42.20 / 76.87 / 114.53 / 143.30 / 175.50 / 208.47 / 235.03 / 280.27 / 318.70 / 352.30）实跑通了，输出 370.500s 与计划零误差。
代价：只配这一版，改一个镜头就得重跑；而且**音乐结构是碎的**——同一首剪成 11 段，副歌永远起不来。观众说不出哪不对，但会觉得「音乐有点平」。

**路径 B · 章节卡补长到小节线 + 事件吸附**（改 1 个常量 + 19 个 timecode，+9.8s）
按 §5.3 两张表改。改完以后整条片子天然卡在 120 BPM，**以后每一期都能直接铺一条连续音乐，不用切**。这是推荐的。

**路径 C · 反过来做**（下一期开始）
先定 120 BPM → 写分镜时每个镜头时长都是 8 分音符（0.25s / 7.5 帧，取 8 帧）的整数倍 → 章节时长是 4 小节（8s）的整数倍 → **一条音乐从头铺到尾，一次都不切**。这是对标博主真正在做的事，也是唯一能让「卡点」变成默认状态的做法。

我的判断：这一期走 B，下一期必须走 C。走 B 是给这一版擦屁股，走 C 才是把卡点变成流程的一部分。

## 7. 仓库里已经有一个卡点引擎，但没接上

查的时候发现 `replica/src/timeline/beats.ts` 已经写好了：

- `nearestBeat(frame, fps, beats, tolerance)` —— 把任意帧吸附到最近的拍
- `onBeatIndex()` —— 返回「第几拍」和「这一拍走到哪了」，可以做脉动衰减
- `isDownBeat()` —— 判断是不是小节首拍
- `BEATS_PER_BAR = 4`
- `BgmSpec` —— 曲名、文件、音量、起止帧、音频内偏移
- `src/components/BeatSync.tsx` —— 一个 `<OnBeat>` 式的包装，带 `accentOnly`
- `scripts/bpm.py` —— 生成拍点 json 的工具

**问题**：`public/bgm/` 里只有一条 `placeholder_112.wav`，是占位的 click 轨（34.29s，-27.5 LUFS）。`DEFAULT_BGM` 指的就是它，而 `toFrame: 11114` 又比片子短，靠 `loop` 硬续。

也就是说：**卡点的基建全在，但从没接过真音乐。** 之前成片里根本没有 BGM（`EP1_final_v1_raw.mp4` 测出来 -19.5 LUFS，基本就是口播的原始电平）。

真要上，三步：

1. 把选好的曲子丢进 `replica/public/bgm/`，跑 `python3 scripts/bpm.py public/bgm/<file> --name <name>` 生成拍点 json
2. 把 `DEFAULT_BGM` 改成新曲子的 name / file / volume，`toFrame` 改成 `FINAL_TOTAL`
3. 需要「只在某章响」就用 `BgmRange`，需要「动效踩拍」就包 `<BeatProvider>` + `nearestBeat`

这一步的性价比最高：**基建已经有了，缺的只是一首真歌和一次配置**。
