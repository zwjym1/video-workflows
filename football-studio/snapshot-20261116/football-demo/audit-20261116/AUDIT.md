# 参考片 / 曼联样片：节奏与视觉工艺证据审计

审计时间：2026-11-16 01:00（中国标准时间，UTC+8）。仅本地只读取证；没有改项目、重渲染、联网下载、联系他人或生成 Page。

## 结论先行

差距不是简单的“分辨率低”或“转场不够花”。样片把**同一回合的动作描述，反复映射到实拍定格和静态全场板**，但没有像参考那样让**人物关系、对手反应、空间命题、视线引导**逐步发生变化。画面粗糙还存在非常具体的硬伤：**脚圈画成正圆、标记无实际跟踪、低对比细线叠在草地上、六个棋子挤在全场板右端、字幕整句反复持留，以及三次夹入源素材的人像转场残帧**。

**建议先验收 12–20 秒的一个因果段，不再硬凑 60–90 秒。** 这只是修改建议，本次未制作新片。参考的 26.933–41.300s（14.367s）已经能完成“看似开放的传球线→侧移缩短距离→断球”的一个可见因果链；不能只学其“停住画面画个圈”。

- **全帧算法扫**：6964 帧全部解码，逐帧降采样为 320×180 灰度后计算相邻帧平均绝对差 MAD、差值>5像素占比、16 桶灰度直方图总变差；不是跳帧抽样。

- “微动”不自动记作新战术信息。参考圈脉动/装饰旋转，与真正增加人物关系、空区、路线、对手位移分开判断；样片的透明渐入也不冒充球员运动。

## 3. 为什么画面看起来糙：同尺度视觉工艺审计

以下左右都统一到 **1280×720显示尺度**；参考先由1080p缩小，样片不因上采样虚增细节。E04裁切均取统一720p图后再2倍显示。主结论不是直接比较原1080p与原720p像素数量。

### A. 脚圈不是地面图形，且没有真正跟踪

- **E01 / E04**：参考28s圈为贴在人物脚下的横扁椭圆/开口弧；红黄各自识别被盯人物与主动人物，传球路线有宽半透明方向带+细虚线。37s和40s，黄圈仍贴随穆勒位置变化，作为侧移/抢断证据。
- 样片 `ring()`（render.py:140–148）边框为 `[x-r,y-r,x+r,y+r]`，数学上就是**正圆**；双环覆盖人物下肢/旁侧草地，不能形成地面透视。样片42s更堆叠了球员环、空当椭圆、对手圆与远角线，黄/棕细线相互干扰，注意力不集中。
- `overlay_shot_mark()`（254–267）虽注释写“interpolate a little”，实现却始终使用同一组 `fz['p11']` 坐标，只按源帧数改变透明度并在n140后关掉；**没有位置插值，更不是跟踪**。定格本身不要求跟踪，但恢复运动时保留固定屏幕坐标会失去贴合。
- 修改建议：先定脚底锚点和本地地面椭圆，按机位标定扁率/方向；运动时对真实逐帧脚位关键点插值并复核，摄影机移动要同步补偿；没有跟踪就恢复播放时清掉圈，不能假装一直贴着。先画主体，再出对手/路线，最后给解释空区，不要同时铺满。

### B. 线条层级和绘制方式，才是“工具感”来源

- 实测代码：实拍主箭头3px、虚线10px/间隔7px；传球箭头alpha230/255，射门提示200/255；外环常为2px。GOLD固定为(232,201,86)，对手标记为偏棕红的CLARET_L。不是简单“所有透明度太低”，而是**细、近草地色、语义不分层、直线与开口V箭头难读**。
- ImageDraw原720p栅格画线；没有路径长度渐进绘制，也没有在矢量/高采样画布绘好后统一抗锯齿缩小的步骤。虚线是逐段line，端点不是独立圆头设计；箭头是两条斜线，缺少清晰端部重量。
- 定格圈线基本共用0.25s渐显；战图a1/a2/a3有透明度先后，**有淡入，不能说完全没动画**，但不等于线从起点长出/球沿线跑/防守跟着变。参考16→19→23s先讲相对安全，再显空区，最后补传球线路；不是三张同一板仅圈在闪。
- 修改建议（不是参考原参数）：720p统一主线3–4px、辅线2px，端点/箭头成套；亮主色与弱辅助色分开，宽方向带仅在解释传球空间时用。路径分段生长，按句子触发；需光晕时用单独柔和底层而不是多套细同心圆。提高绘图采样后缩回720p可以改善边缘，**不是把导出尺寸改1080p就算修好**。

#### 慢放的中间帧也没有补：背景状态重复，并非真正30个新动作帧/秒

`src_index()`使用整数下取整选源帧，没有光流/混帧。逐帧推导：开场8s仅130个实拍状态（16.250个/秒），play3为53个状态/3.033s（17.473个/秒），slow_shot为29个状态/2.333s（12.429个/秒），最后一段每个背景源帧最多连续重复3个输出帧。详见 `sample_motion_cadence.csv`。这不是“输出30fps就很顺滑”；它是可验证的低动作采样机制，未据此冒称本人观看时听感/流畅度结论。正常25→30fps转换也会有重复帧，不能一概当故障。修改优先减少不必要的慢放，原速动作配短定格；若之后用运动插值，必须检查脚和球形变，不能把生成轨迹当真实战术证据。

### C. 战图是构图/语义不足，不是缺几个球场装饰

- **E02 / E05**：样片33s把全场横向铺开，只有2名进攻球员和4个对手点集中在右侧，大片空场抢占画幅。球场本身已有中圈、禁区、六码区、罚球点、球门，不应误诊为“没画球场细节”；问题在于**无关球场很大、关键关系很小**。
- 所有POS是静态示意坐标；曼联红(196,42,42)与维拉暗红(118,52,74)同属深红系，弱化双方辨识。球员点16px半径，相对980px宽的场图显小；没有“防守者先被谁牵动、哪片区域因此打开”的可见变化。
- 参考13→23s能看到局部推近、焦点轮换、红黄含义变化、空区与线路标签递进。它也用简化棋子，但棋子、板镜头和解释是一体的；不能把“多做发光纹理”当战术能力。
- 修改建议：以真实回合局部半场/禁区构图，保留判断空间必需的防守者和球门关系；用浅蓝/灰等对比维拉点与曼联红；让球、跑位、对手反应按源画面状态变化，局部标签如“传球线路”“无人照看”必须有真实帧证据。不要把当前示意米制坐标包装成实测距离。

### D. 字幕没有参与讲解，整句和字体层级反复重置

- **E03**：参考37s可读“让穆勒和球之间的距离更近了”，其中人物和因果重点为黄色；16s用红色强调“德容/相对安全的位置”，23s强调“传球线路”。底字与人物小标签分层。
- 样片字体本身是可用的Noto Sans SC，不应把“糙”归咎字体品牌。实际为实拍34px、战图30px，白字+3px偏移描边，未单设阴影/字距设计；标题52px。不同镜段整句重复、大小切换，却没有语义着色。
- s1/s2各17汉字，先挂在定格再挂在战图：各累计可见约8.7s（中间因换板短暂消失）；s3为21汉字整句。总结12字从45.267留到51.333，VO却47.451已结束。参考也有长整句，**不能说“参考全是短字卡”**；其优势是关键词与图形同步解释。
- 修改建议：按新信息单元换句而不是按镜段重新放同一句；主字幕、球员号、小标签三级明确。可试5–12字短分句、关键词着色（这是建议，不是参考实测均值）；字幕退场随这句口播/论点结束，不为填时长硬挂着。

### E. 三次“闪出大人脸”是素材切头问题，不是审美偏好

- **E06**精确抓取：F240=8.000s、F458=15.267s、F1540=51.333s，都有前一近景人物叠在球场上；前两帧后的截图仍能看到残影。
- 三处分别是完整首看、拆解重启、完整复看的n0源帧。源片开头尚处官方叠化中，被重复拿来起镜。不是凭空猜测闪屏或编码损坏，源帧与工程n0映射可核对。
- 修改建议：选干净动作首帧再切回，重新对齐源音频；删掉源转场污染，不要添加更多转场遮丑。

## 4. 原生720p与重编码损失，分别占什么问题

- 底片本来就是720p/25fps，视频约1.036Mbps；现成JPEG输入也是1280×720。草地与远处看台在输入上已经偏软，不能指望升1080p恢复不存在的细节。参考片来自不同场次/编码来源，不能用不同内容全局PSNR声称谁清晰多少。
- v2母版同为1833帧720p，视频约1.718Mbps；light约1.064Mbps。**码率降低本身不是视觉损失定量结论。**
- E07用同一底片n78，对照成片F840=28s。仅选未覆盖绘图的平坦草地ROI `(x80:350,y450:600)`：输入JPEG→light RGB-PSNR 45.709dB、MAE1.010/255；母版→light 50.641dB、MAE0.367/255。该ROI里的追加编码差异较小，见 `quality_roi_metrics.json`；**没有全片/看台/高速球/字幕SSIM测量，不能外推为全片无压缩损失**。
- 但正圆、错误贴合、固定坐标、大片空白、同色语义、无路径绘制、源叠化残帧，在输入/母版阶段就存在，改CRF或升分辨率不会消除。之后可优化单次高质量编码，但应排在构图/动作/标记工艺之后。

## 5. 战术命题与信息量：避免把动作描述当分析

计数口径：能单独表达“观察/位置/诱导/对手反应→为什么有利”的不同关系记为一个分析命题；“接球、传球、射门”仅是动作步骤，不因为换一张板重复算命题。以下是**叙事内容编码，不是证明作者每个战术推断都客观正确**；参考“16秒”等结论亦未独立校验。

参考全片至少有以下 **9组不重复的分析关系**（ASR辅助、精确画面与全片联系表交叉）：
1. 13–30s：德容看似安全、传球线看似开放，实际上是诱导；16/19/23/28s有真实字幕证据。
2. 33–41s：先侧移，缩短与球的距离，再抢断；35/37/40s有明确画面/字幕。
3. 43–50s：带球推进并分边，把断球转换成快速反击。
4. 50.7–60.2s：高位防线留下身后空间，边路威胁迫使对手回防。
5. 62.3–71.4s：穆勒放慢、回头观察、发现没人跟后再举手。
6. 71.7–79.3s：后卫目光集中边路，弧顶区域无人注意。
7. 89.6–98.5s：假射吸引封堵，再垫给莱万。
8. 101.1–110.2s：先外跑牵动阿尔巴，再改变方向内切。
9. 110.3–119.5s：背身回做落到跑动线路，完成撞墙与终结。

前45s已经包含前两组完整关系，并开始第三组；不是等45秒才有内容。122.6–141.3s总结以编号串联4个不同阶段，而非再讲同一句。

样片覆盖同一底片182帧（25fps，共7.28s，首末帧中心621.76–629.00s，含末帧持续），开场已用其中一段，8–15.267和51.333–58.6又两次完整重放，中间再拆解。它只有 **3步动作描述**（拿住/推进传入/出脚）和 **1个宽泛总结**“空间就出在这一传、一插之间”，没有独立交代哪个防守者因何改变位置、何时失去对11号的照看、跑动先后为何影响射门。

这能证明重复和信息不足，**不能据此臆测制作者主观上故意凑时长**。参考也会放慢和复看，慢并非原罪；关键是慢下来时是否持续证明新关系。当前样片不具备撑满61秒的已写信息。

## 6. 不先重做：五条修改顺序/验收标准

1. **先删空等和污染帧，再做12–20秒单因果验证段。** 不保留三块6.4s定额战图；按一句论点需要的证据定长度。删去n0叠化残影；提问后立即进证据。验收：没有口播结束、标记齐了还原地等待数秒的板尾。
2. **先确认能证明什么，再写台词/画防守变化。** 用当前真实底片验证“持球者/防守者/11号”的关系；若镜头不能证明盲侧/牵制，降低为射门配合路径讲解，不编空间战术。只保留一个可被画面证实的原因及其结果。
3. **重建一套脚圈/路线/跟随工艺小样。** 同一实拍镜头内校正地面透视、锚点、遮挡与运动；真人恢复运动时无固定坐标漂圈；亮主线、弱辅助线和可读端点；路径生长随解释出现，而不同时端出全部标记。
4. **重排局部板，不靠添纹理。** 减掉无关空场，放大人物关系；双方有对比、人物/球随真实事件递进；先人物→再路线→最后空间解释。不能用示意坐标假装位置测量，不能把光晕脉动算信息推进。
5. **把字幕并入镜头节奏，并最后优化编码。** 按论点切分、关键词有层级，去掉跨实拍/板的无意义整句重复；先统一视觉比例再比精致度。素材清晰度受原生720p约束，绘图可高采样再缩回、减少编码代数，但不以“升1080p”交差。

工程 `render.py:1–7` 自己注明 Python/Pillow、非官方Lemo-Opuscar引擎，仅从可见结构提炼风格。这与完成参考逐镜/逐动作复现不是一回事；也不代表改用任何特定软件就自动达到参考工艺。此次没有修改实现或代换方案。
