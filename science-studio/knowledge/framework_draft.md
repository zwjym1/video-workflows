# 「让 AI 动手」单集框架 · 草案 v0（2026-11-02 UTC+8）

标记：【说】=博主原话/明确主张；【推】=我们的推断，未验证。

## 0. 定位一句话
【推】O（人类）想让 AI 替他做件真事 → 大肥鱼（AI 本人）热情但“只会动嘴/乱动手” → 一个概念（MCP/Skill/Agent…）让她真正动手 → 观众看完照做一步。
依据：【说】老明“看完至少在物理世界产生一个动作”；“行为触发”是好作品第一层。阿柠金句“只有真正能让 AI 替你动手，才能算是多了一个帮你打工的分身”。

## 1. 钩子类型（0–3 s，选 1 主 + 1 辅）
| 类型 | 来源 | 我们的写法示例 |
|---|---|---|
| 身份认领（难以量化的好特质+落差） | 【说】编导“你是不是有想法有认知，但是做不火选题” | “你是不是天天用 AI，但活还是你自己干？” |
| 反常识/否定全网 | 【说】老明“全网对算法的分析大多是做题家思维” | “全网都在教你写提示词，其实问题根本不在提示词” |
| 结果先行的演示（MOCK 窗口蒙太奇） | 阿柠 EP 拆解 | 0 s 就是大肥鱼操控 PS/Blender 的画面 |
| 一句立论悬念 | 【说】“我们的答案是恐惧” | “答案是：她没有手。” |
| 时长/狠话承诺 | 【说】“给我两秒”“看不懂过来杀我” | 【推】慎用，和我们的轻萌风格冲突，可由大肥鱼说出变成笑点 |
检查四判断【说】：和我有关吗？我在乎吗（损失/欲望）？和我想的一样吗（预测误差）？能立刻看懂吗（踮脚可得）？

## 2. 留存机制
1. 【说】编号框架+手势/卡片当章节信号（编导 4 判断、老明 3 恐惧）→ 我们用顶部章节 tab + 大肥鱼开章提问（阿柠 6/8 章）。
2. 【说】每个抽象点=生活比喻+案例+数据图（聚会、扮猪吃老虎、行为链）→ 我们：每个术语一个比喻（大脑/手、USB、遥控器），首尾回扣。
3. 【说】预测误差：“答案和他预测一样就没必要停留”→【推】大肥鱼提出“直觉答案”，O 第一拍否定（与 aning 规则 #3 一致）。
4. 【说】自我拆解/元钩子（“这条视频的选题已经完成了使命”）→【推】片中可让大肥鱼当场演示本集技能做的东西就是本片素材。
5. 【说】信息密度：删气口、慢处倍速、快 BGM（编导）；视觉单元每 3–4 s 换（阿柠实测）。
6. 【说】“踮脚可得”：每集 ≤3 个术语。

## 3. 系列与关系（算法侧）
- 【说】老明：平台从注意力竞争转向“关系深度”；“下个礼拜你来，我还在这里，我会讲一个更有意思的话题”。→【推】每集结尾大肥鱼预告下集“我想学会××”，形成约定。
- 【说】编导：爆款系列“省去用户判断成本”；延续感来自未完结叙事或数字（“第X期”“用N期带你…”）。→【推】标题统一“让 AI 动手 第N期｜…”，开场一句“大肥鱼已经学会了 N 个技能”（技能计数=世界观进度条）。
- 【说】系列生命周期 3–6 个月，疲软时调整。【说】可做“考卷”复习篇回收知识点。
- 【说】垂直两入口：一个需求 / 一个人群。【推】我们锁“想让 AI 替自己干活的普通人”这一需求。
- 【说】老明概念五阶段：命名→增殖→解构→“肉身指令”。【推】AI 术语正处增殖/疲劳期，我们的卖点=不解释概念本身，而给“动手指令”。

## 4. 角色关系规则（O vs 大肥鱼）【推，参照阿柠】
1. 大肥鱼是 AI 本人：热情、自信、偶尔傲娇（“哼，这不就是模型不够聪明吗？”），代表观众的直觉误解。
2. O 是人类：冷静、给答案、偶尔被大肥鱼吐槽；不能比大肥鱼更“可爱”。
3. 每章由大肥鱼一句问题开（≈10% 时长 2SHOT），O 第一拍否定直觉，再给比喻。
4. 笑点来自人设翻车（被工具淹没、手伸不到软件），每 30 s ≤1 个梗。
5. 结尾：大肥鱼真的动手成功（技能+1）→ O 金句 → 大肥鱼预告下集。
6. 互动设计【说：评论=共情或反驳】：结尾抛给观众“你最想让大肥鱼帮你干什么活？”——评论区即下期选题库（关系深度）。
