# 电脑与 AI 轻量选题系统 v2026.11.17.7

主方向是电脑与人工智能，题型不固定。可以做已火科普、近期热门技术、新产品机制、真实争议和可实测现象。不是必须先有爆款成片，也不是只做硬件。

本文是规则和卡片约定，不是网站、表格或每日自动任务。选定题目之后，制作仍走已批准的三门（见制作工作流 v2026.11.17.1）：选版后先审实际选图、静态关键帧和逐镜 → 通过后才做连续带声代表段 → 用户审过样段再出全片及发布包。不在选题阶段写完整稿、不生成音视频。

## 1 每轮怎么做

需要筛题时按本规则在当次会话里执行，不设日更例行任务，也不恢复旧热搜快照例行任务。

每轮按阶段分层，不要把时间耗在已经圈定的一两道旧题上补材料：

1. **先广泛发现**：内部先登记不少于约 12 个不同的、有可追溯来源的具体问题或方向。来源优先真实作品和评论/搜索需求、以及近期官方技术或产品现象。覆盖电脑真实使用疑问、AI 普通用户关心的机制、近期热门技术或产品现象等不同入口，不预设「X越大一定越好吗」这类固定标题，不把题池收窄成装机参数，不一律做成购物选择，也不只盯已有几个作者——须复用作者库，同时主动发现新作者和新作品。没有核到的作品就写未核到，不为凑数编需求或作品，也不向用户报告不存在的供给。官方或平台热搜当时没有电脑/AI 词，只说明该榜没有这些词，不等于垂直领域没有热点，还须查垂直优质创作者的近期内容和相关官方来源。
2. **再挑约 5–6 个最有潜力的题补证**：按第 1.1 节把需求、供给竞争、未满足机会与质量提升、热点及持续传播四块证据分开写全，并实际拆结构和画面。当日热点和已经火了的优质视频都要看，但不能只交题库链接，也不能只用热度或点赞代替需求。同题 8 底线 / 10 目标不是这一步的前置条件，不要为了先凑满 8 条而不再拓题。
3. **再交用户可读候选**：直接给 3–5 条候选简报。证据不足时允许少于 5 条，宁缺毋滥，不硬凑不同的题来凑数，也不得反复只交旧的两三题外加一个跨题储备来代替开拓。只有标题、互动数字等 metadata、尚未实际拆结构和画面的，必须标「初筛」，不得包装成最终推荐或首推。这不是新增要用户确认的步骤：仍一次交出列表，由用户定题。面向大众的短名单不硬塞窄技术基础设施题（例如主要面向部署或编程的推理框架课）。旧候选没有预留名额，也没有排序优先；若仍进入最终名单，必须写明胜过哪些新题的实际理由。
4. **用户定题之后**：再对同一道题做深调研（同题优质视频、开头、评论、相关搜索），此时才执行同题 8 底线 / 10 目标。深拆过程中先写下这一个观众具体问题、贯穿的真实任务或物件（或显式不用额外例子）、以及必要机制，供制作侧写稿前锁定。未定题前，不把未看完的同题材料写成已经充分。内容优先不是禁止把机制讲准，也不是要求每道题都改成固定的生活例子题型。

推荐排序以质量最优为目标，只依据第 1.1 节四块证据。制作或核验成本、好不好做、费不费时不参与排序，也不能当作推荐理由。不能主要因为「贴近面试」或「更好做」就把某题放成首推。

## 1.1 每轮选题的四块证据与推荐边界

每轮必须同时收集并分开写清下面四块。缺哪一块就标「未知」，不补编、不打分、不加权重。

1. **需求**：具体受众场景；搜索与评论里重复出现的问题；这些证据的时效和范围。点赞、收藏或转发不能替代需求。写法沿用旧实地包，而不是只勾「已采集」：评论用可引用原话或合并问法，目标 ≥12 条，并写一句「观众真问什么」；相关搜索必须来自搜索页联想和视频页看后搜，各至少 3 词，不自己编词；某侧达不到就如实写不足，不能用搜索联想冒充看后搜，也不能把页面级、可能串台的词当成该片已核推荐词。旧系统有这些采集方法，但没有把需求写成压过热榜分的推荐主依据；现在按质量最优把它们接上。
2. **供给竞争**：严格同题的多作者样本；分布与时效；头部作品和讲法同质化的可见证据。同质化或头部判断须来自实际拆过的结构与画面；还没拆就写未拆，不能把 metadata 当成已经看清竞争。最终推荐的同题样本须实际看片，记下 0–5s 画面和口播原文（禁止「开头很炸」「讲了原理」这类空总结；听不清标听不清）。并写清同切口是否已有打得响的作品（旧称「撞车」），作为供给观察，不打分。
3. **未满足机会与预期内容质量提升**：现有供给还没讲清或讲不好的点，以及若做本题能在内容质量上具体提升什么。优先写旧实地包里的「爆款没讲、评论在追问的点」。制作成本不能替代价值。
4. **热点及持续传播证据**：仍按第 2 节把官方榜、第三方榜、媒体或官方发稿、单条作品互动分开写。这只是传播证据，不能单独代替需求或价值。

红海或蓝海是用户后来新增的有限判断，旧选题 SOP 没有这一专章，不能写成旧已有。只在「需求」和「供给」都有证据时才判断，可写红海、蓝海、混合或未知，并写依据；旧「撞车/切口」观察可作供给材料，但未拆结构和画面时不得称已经做了红蓝海评估。没有搜到、接口失败、或同题条数少，都不等于蓝海。没有足够数据就标未知。不得自行造评分、权重或红蓝海指数。不恢复旧的热榜 40%、产能 20% 或「实地不替代热榜分」。

制作成本与核验成本（含难不难做、费不费时）若为后期排期需要，可另行记录，但不得出现在推荐理由里，也不得用来压过质量或需求。

列为最终推荐的候选，其优质成片依据必须已经实际拆过结构和画面，并留下 0–5s 画面与口播原文。只有 metadata 的条目一律标初筛，可以留在列表里对照，但不能写成最终推荐。公开热榜、聚合榜或单条点赞只做初筛，不能单独定题。

不恢复午晚双槽、固定打分闸门或额外要用户确认的步骤。安全类红线（地缘时政、猎奇二次传播、未成年人与隐私、无依据贬损）可作为排除理由，不再打 15 分。发布后若用户提供真实后台数据，回填 24h/72h 的 2 秒跳出、5 秒、均播、完播，只用于复盘质量，不反哺任何权重。

### 每轮交给用户的可读简报

一次交给用户 3–5 条（证据不足可以更少），必须是可读摘要，不能只丢链接或路径。每条至少包括：

- 初筛或最终推荐
- 这一个具体问题
- 需求要点：受众场景、观众真问什么、搜索词来自哪一页、证据时效和范围
- 供给要点：同题多作者样本做到哪一步（仅 metadata / 已拆 0–5s 结构与画面）、撞车观察
- 未满足机会，以及若做能在内容质量上提升什么
- 热点及持续传播证据（官方榜、第三方榜、单条互动分开写）
- 有需求且有供给证据时，才给红海 / 蓝海 / 混合的有限判断；否则写未知
- 该题同题 8/10 是否已满
- 不用制作成本、核验成本或「好做、省时」作为推荐理由

用户定题之后，再按上述实地质量标准把该题深拆补齐，然后才进入写稿和制作三门。


## 1.2 参考作品的时效与现状适用性

同题内容和跨题形式参考都优先选用比较新的作品，尤其是 AI、模型产品、平台功能等发展较快的领域。每一条参考须记录：作品发布时间、本次采集时间、以及它讲的功能或机制对现状是否仍适用。

- 不得擅自划定「早于某年某月一律不用」的硬性日期门槛。新与旧是相对当前发展而言，要看内容是否还跟得上，而不是只看一个固定截止日期。
- 变化快的领域必须用当前可核对的一手资料（官方说明、当前产品界面，或可复查的近期作品）核实机制是否仍成立。旧片里的功能名、限制、操作路径或结论，不能直接当成今天的事实。
- 较旧的作品可以单独留作历史对照或表达、结构参考，并明确标注用途。它们不能用来证明现状，也不能拿来凑同题 8/10 的条数。
- 历史高互动仍然可用，但必须同时写清发布时间和现状适用性，不能写成今天仍适用的新证据。

## 2 热点与优质视频怎么标

官方热榜、第三方聚合榜、媒体报道、官方发稿、单条作品互动，必须分开写，不能混成「今天很热」。

每一条热度记录尽量写全：来源名称、是官方还是第三方、榜位、热度值、抓取或页面标注时间（Asia/Shanghai）、链接。缺哪一项就标明缺失，不要补编。

- 今日热搜查不到或接口失败，就写未取得，不编榜。
- 官方发稿或媒体报道只证明有人在发布或转述，不自动等于大众热搜。
- 第三方聚合榜不能冒充官方榜；同一词在两类榜上的名次、是否仍在榜，要分别写，并记下抓取时间。
- 历史高互动可用，必须标明作品发布时间和本次数据采集时间，不能写成今天新爆。点赞不等于播放，也不能替代需求。
- 热词原义还没核清时，不得把主观猜测的科技切口写成榜单原义，也不得因此列入正式候选。

证据等级仍为三选一，不能混写：

- **已验证高互动**：有原作品链接，以及点赞、评论、收藏或转发中至少一类公开数字，并同时写清发布时间和采集时间。缺项写 null。
- **新技术有关注证据**：有近期真实事件、官方发布或可查讨论，且来源已打开或可定位。这只证明有人在谈，不证明已经有爆款成片，也不证明已上热榜。
- **待验证**：问题可能成立，但今日没有足够的互动数据或可定位新证据。可以入库，不能称为已经火了或今天新热。

观察证据和主观判断分开写。不做成功概率、完播预测或保火承诺，也不自行造综合评分或权重。点赞不等于播放，也不能替代需求。价值依据第 1.1 节机会与质量提升来写，不能用制作或核验成本代替。成本如需记录，只进执行排期，不写高/中/低来参与推荐。

## 3 同题深调研（仅用户定题之后；底线 8、目标 10）

「底线 8 条、目标 10 条」指的是**同一道题**要实际看的优质视频数量，不是每轮要交 8 道不同的题。

对列入候选、尤其是准备定稿的题，要记录：

- 范围：什么算同题（必须是同一具体问题；领域相邻或「都是 AI / 都是硬件」不能顶替）
- 同题内容依据与跨题形式参考分开列出；跨题只学讲法或视觉承担解释的方式，不把其题材结论当本题机制
- 尽量覆盖多作者，不只堆同一作者的同质条
- 已看条数、其中完整看了开头 0–5 秒画面和口播原文的条数。计「已看开头」必须是实际看片后的画面记录 + 口播原文（或听不清标记），接触纸或空总结不算
- 评论高频是否达到可引用原话或合并问法目标 ≥12，并已写「观众真问什么」
- 相关搜索是否同时有搜索页联想和视频页看后搜，各至少 3 词；不编搜索词
- 是否已写同切口撞车，以及「已有作品没讲、评论还在追问」的点
- 状态：未开始 / 未满 / 已满
- 看图/看片所用模型、材料范围和日期；历史 Qoder 或其他模型记录保持原标签，不改写成 Gemini 3.8 已看
- 各条参考的发布时间、采集时间，以及对现状是否仍适用；旧片若保留，须标明只作历史或表达用途

规则：

- 不到 8 条就如实写「未满」，把已有条数和缺什么交给用户决定是否继续、换切口或换题。不得擅自宣布这条规则永久豁免，也不得用不相干视频硬凑，也不得用不能证明现状的旧片凑数。
- 未观看就不能说已经分析了文案或画面。关键帧、开头拼图、接触纸不等于连续播放，也不等于实听。旧标准是实际播放 0–5s 并照抄口播原文；看图默认仍用 Gemini 3.8 Flash 中等，历史其他模型记录不改标签。
- 口播原文必须来自本轮能核对的听写或字幕。旧的自动转写若未复核，只能当参考，并写明限制；不能当成已核对的口播原文去引用。听不清就标「听不清」。
- 按旧实地要求，开头 0–5 秒画面和口播原文、评论高频、相关搜索这三项没齐之前，不能定稿口播。

热门技术题可以暂时没有同题成片，但必须如实注明「同题看片 0」，不能把「可以没有成片」写成已经调研充分。

## 4 本周期排除与卡片

- 刚做完的芯片分档 / 5070 Ti 残次品本周期不入库重做。
- 2026-11-17 正式候选不选盐和鱼两题，避免和当日已报过的生活科普重复；它们可作为已核高互动作品留在说明里，不默认当新题。
- 当日正式候选写在 `TODAY_YYYYMMDD.md`（3–5 条，或证据不足时更少）。题库在 `topics.json` 与 `topic_cards/`。
- 卡片字段见 `templates/topic_card.json`，须能记录：今日角色、候选包装（初筛仅 metadata / 最终推荐已拆结构与画面）、证据等级、热度来源（官方/第三方分开）、第 1.1 节四块证据（含评论原话、联想/看后搜、观众真问什么、撞车与评论追问缺口）、有限的红蓝海判断（无数据则未知；此项为用户新增）、同题条数与未满状态、同题内容依据与跨题形式参考（含发布时间与现状适用性）、观看状态与看图模型记录、口播/转写限制、普通观众疑问（不是面试理由）、贯穿任务或物件、必要机制、概念清单、价值（不由成本代替）、时效、事实来源、原创演法、仅供排期的成本记录、观察证据、主观判断。发布后若有真实后台数据，再填 24h/72h 留存指标，不反哺打分。发布后表现只留空模板，等用户提供真实后台数据，见 `templates/postmortem.json`。
