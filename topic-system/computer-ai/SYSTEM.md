# 电脑与 AI 轻量选题系统 v2026.11.17.2

主方向是电脑与人工智能，题型不固定。可以做已火科普、近期热门技术、新产品机制、真实争议和可实测现象。不是必须先有爆款成片，也不是只做硬件。

本文是规则和卡片约定，不是网站、表格或每日自动任务。选定题目之后，制作仍走已批准的三门：完整方案含实际选图和读音 → 连续带声代表段 → 全片及发布包。不在选题阶段写完整稿、不生成音视频。

本版继承已核旧选题系统里仍然有效的要求，不恢复午晚双槽、旧角色名称或旧打分权重。

## 1 每轮怎么做

需要筛题时按本规则在当次会话里执行，不设日更例行任务，也不恢复旧热搜快照例行任务。

1. **先调研**：同时看当日热点和已经火了的优质视频，两者都要做，不能只交题库链接。
2. **再交用户可读候选**：直接给 3–5 条候选简报。证据不足时允许少于 5 条，宁缺毋滥，不硬凑不同的题来凑数。
3. **用户定题之后**：再对同一道题做深调研（同题优质视频、开头、评论、相关搜索）。未定题前，不把未看完的同题材料写成已经充分。

筛选顺序：先看普通观众会不会问、看完能不能分清一件具体的事；再看时效、事实来源、真正同题参考、原创空间、视觉演法、素材、成本与障碍。不能主要因为「贴近面试」就把某题放成首推。

## 2 热点与优质视频怎么标

官方热榜、第三方聚合榜、媒体报道、官方发稿、单条作品互动，必须分开写，不能混成「今天很热」。

每一条热度记录尽量写全：来源名称、是官方还是第三方、榜位、热度值、抓取或页面标注时间（Asia/Shanghai）、链接。缺哪一项就标明缺失，不要补编。

- 今日热搜查不到或接口失败，就写未取得，不编榜。
- 官方发稿或媒体报道只证明有人在发布或转述，不自动等于大众热搜。
- 第三方聚合榜不能冒充官方榜；同一词在两类榜上的名次、是否仍在榜，要分别写，并记下抓取时间。
- 历史高互动可用，必须标明作品发布时间和本次数据采集时间，不能写成今天新爆。点赞不等于播放。
- 热词原义还没核清时，不得把主观猜测的科技切口写成榜单原义，也不得因此列入正式候选。

证据等级仍为三选一，不能混写：

- **已验证高互动**：有原作品链接，以及点赞、评论、收藏或转发中至少一类公开数字，并同时写清发布时间和采集时间。缺项写 null。
- **新技术有关注证据**：有近期真实事件、官方发布或可查讨论，且来源已打开或可定位。这只证明有人在谈，不证明已经有爆款成片，也不证明已上热榜。
- **待验证**：问题可能成立，但今日没有足够的互动数据或可定位新证据。可以入库，不能称为已经火了或今天新热。

观察证据和主观判断分开写。不做成功概率、完播预测或保火承诺。成本与价值只给高 / 中 / 低和理由。

## 3 同题深调研（定题后，底线 8、目标 10）

「底线 8 条、目标 10 条」指的是**同一道题**要实际看的优质视频数量，不是每轮要交 8 道不同的题。

对列入候选、尤其是准备定稿的题，要记录：

- 范围：什么算同题（必须是同一具体问题；领域相邻或「都是 AI / 都是硬件」不能顶替）
- 已看条数、其中完整看了开头 0–5 秒画面和口播原文的条数
- 评论高频、相关搜索是否已采集
- 状态：未开始 / 未满 / 已满

规则：

- 不到 8 条就如实写「未满」，把已有条数和缺什么交给用户决定是否继续、换切口或换题。不得擅自宣布这条规则永久豁免，也不得用不相干视频硬凑。
- 未观看就不能说已经分析了文案或画面。关键帧、开头拼图、接触纸不等于连续播放，也不等于实听。
- 口播原文必须来自本轮能核对的听写或字幕。旧的自动转写若未复核，只能当参考，并写明限制；不能当成已核对的口播原文去引用。听不清就标「听不清」。
- 按旧实地要求，开头 0–5 秒画面和口播原文、评论高频、相关搜索这三项没齐之前，不能定稿口播。

热门技术题可以暂时没有同题成片，但必须如实注明「同题看片 0」，不能把「可以没有成片」写成已经调研充分。

## 4 本周期排除与卡片

- 刚做完的芯片分档 / 5070 Ti 残次品本周期不入库重做。
- 2026-11-17 正式候选不选盐和鱼两题，避免和当日已报过的生活科普重复；它们可作为已核高互动作品留在说明里，不默认当新题。
- 当日正式候选写在 `TODAY_YYYYMMDD.md`（3–5 条，或证据不足时更少）。题库在 `topics.json` 与 `topic_cards/`。
- 卡片字段见 `templates/topic_card.json`，须能记录：今日角色、证据等级、热度来源（官方/第三方分开）、同题条数与未满状态、观看状态、口播/转写限制、普通观众疑问（不是面试理由）、价值、时效、事实来源、原创演法、成本与障碍、观察证据、主观判断。发布后表现只留空模板，等用户提供真实后台数据，见 `templates/postmortem.json`。

- 本地研究目录与公共 zip 只收文本和 JSON，不收第三方视频、截图、完整转写、评论全文、凭据或私人路径。
- 网盘放在「工作流」下已有的独立目录「电脑与AI选题系统」，更新同目录已有文件，不新开一套系统目录，也不写进「简洁实物融合科普_v2026-11-17」发布包。
- 仓库若日后写入，建议独立目录 `topic-system/computer-ai/`，只给根 README 加导航；不要覆盖已有 `topics-workflow/`，也不要把本库混进制作工作流目录。本轮不在 GitHub 上写入。
